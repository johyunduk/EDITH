# 공방 체인 · 엔진 만들기

말: **노드**(일 하나 — 스킬 · 명령, 엔진에서는 체인 · 엔진도) → **체인**(노드를 이은 것, 예: 「기획 파악」) → **엔진**(체인 · 엔진을 이은 것, 예: 「기능 개발」) → **런**(체인이나 엔진을 한 번 돌린 것 — EDITH 「런」 메뉴).
체인과 엔진은 파일 꼴이 같다 — 공방 폴더의 하위 폴더 하나, `engine.json` 하나. 종류는 `engine.json` 의 `kind`(`chain` · `engine`)이고 사용자가 화면에서 만들 때 정한다 — 고치지 않는다.
**체인**은 스킬 · 명령 노드만 넣는다. 다른 체인 · 엔진을 부르는 노드(`"engine": "<폴더>"`)는 **엔진**에만 넣는다. 체인을 고치다 다른 체인을 넣어야 하면, 엔진을 새로 만들어 거기에 넣자고 말한다.

체인이나 엔진 하나를 만들거나 고친다. 남기는 것은 둘이다.

- `<폴더>/skills/<이름>/SKILL.md` — 노드가 쓸 스킬
- `<폴더>/draft.json` — 노드 · 화살표 초안. 사용자가 EDITH 화면에서 「미리 보기 → 적용」 하면 그대로 바뀐다.

`<폴더>/engine.json` 은 고치지 않는다 — EDITH 화면만 쓴다(같이 쓰면 사용자가 캔버스에서 고친 것이 사라진다).

## 0. 어디서

- 공방 폴더는 `~/.local/share/edith/workshop/` 이다. 체인 · 엔진 하나 = `engine.json` 이 있는 하위 폴더 하나.
- 사용자가 이름으로 말하면 각 폴더 `engine.json` 의 `name` 으로 찾는다. 없으면 「EDITH 공방 왼쪽 「새 체인」(또는 「새 엔진」)으로 먼저 만들어 주세요(폴더 이름은 영문)」 라고 하고 멈춘다. 만들 것이 다른 체인 · 엔진을 부르면 「새 엔진」 이다.
- `engine.json` 의 `kind` 로 체인인지 엔진인지 먼저 본다. 고치는 거면 `engine.json` 과 `skills/` 를 먼저 읽는다. `draft.json` 이 이미 있으면 그것을 이어 고칠지 묻는다.
- 스킬 하나만 써 달라는 부탁이면 3절만 하고 `draft.json` 은 쓰지 않는다(사용자가 노드에서 「연결」 을 누른다).

## 1. 묻기 — 초안 전에

하는 일이 흐리면 질문 창(AskUserQuestion)으로 하나씩 묻는다. 이미 말한 것은 다시 묻지 않는다. 보통 3~6개면 된다.

- 한 번에 질문 하나, 고르기는 하나만 — 여러 개 고르기(multiSelect)는 쓰지 않는다(EDITH 질문 카드가 보내지 못한다). 고를 것이 여럿이면 질문을 나눈다.
- 선택지에는 추천을 맨 앞에 두고 「(추천)」 을 붙인다.

물을 것(필요한 것만):

1. **받는 것** — 런 입력(예: 기획서 링크)과 앞 체인이 남긴 파일
2. **남길 것** — 끝나면 무엇이 있어야 하나(문서 · 코드 · 파일), 다음 체인에 넘길 파일 이름
3. **단계** — 사람이 하는 순서대로
4. **사람 확인** — 어디서 멈춰 사람에게 물을지
5. **검증** — 통과를 무엇으로 확인하나(테스트 · 린트 · 스크립트). 명령이 있으면 명령 노드로 만든다
6. **실패하면** — 고치고 다시 할지, 몇 번까지
7. **이미 있는 스킬** — 가져다 쓸 설치 스킬이 있나

작업 폴더(런 시작할 때 고르기 · 늘 같은 폴더 · 새 워크트리)와 공통 규칙은 화면 설정이다 — 필요하면 화면에서 고르라고 끝에 알려 준다.
작업 폴더는 돌리는 맨 바깥 것(보통 엔진)의 설정만 쓴다. 공통 규칙은 엔진에 두면 안에 든 체인에도 붙는다(체인에 자기 공통 규칙이 있으면 그것).

## 2. 노드 나누기

- **노드 하나 = 산출물 하나**(예: 「요약 문서」, 「API 코드」). 한 노드가 여러 산출물을 만들면 쪼개고, 떼면 의미 없는 일은 합친다. 보통 3~8개.
- **확인은 되도록 명령 노드로** — Claude 의 "통과" 보다 끝 코드가 믿을 만하다. 예: `npm test`, `pytest -q`, `$EDITH_ENGINE/check.sh`(그 폴더에 스크립트를 같이 쓴다).
- **실패하면 고치고 다시** — 확인 노드에서 고치는 노드로 `"fail": true, "max": 3` 화살표. 런에서 확인이 실패하면 EDITH 가 고치는 노드를 돌리고 확인을 다시 돌린다(최대 max 번). 고치는 노드에는 다른 화살표를 잇지 않는다.
- **사람 확인**은 노드 종류가 따로 없다 — 그 스킬 안에서 질문 창으로 묻게 쓴다.
- **엔진**(여러 체인 · 엔진을 잇기)은 노드가 체인이나 엔진을 가리킨다: `"engine": "<폴더>"`(칸 이름은 `engine` 그대로). 엔진 안에 엔진도 된다(예: 「개발」 엔진 → 「검증」 엔진). 스킬 · 명령 노드를 섞어도 된다. 체인 사이에 넘길 파일 이름을 정해 앞 체인의 마지막 스킬과 뒤 체인의 첫 스킬에 같이 적는다. 런에서 체인 · 엔진 노드는 그 자리에서 그 안의 노드들로 펼쳐져 돈다(같은 작업 문서). 체인 · 엔진 노드에는 「실패하면」 화살표를 잇지 않는다 — 고치고 다시 하기는 체인 안의 노드끼리.
- 보통 화살표로 고리를 만들지 않는다 — 되돌아가는 길은 실패 화살표뿐이다.

## 3. 스킬 쓰기 — `<폴더>/skills/<이름>/SKILL.md`

- 이름은 영문 소문자 · 숫자 · `-`(40자까지), 그 폴더 안에서 겹치지 않게. 맨 위 frontmatter 에 `name` 과 한 줄 `description`.
- 런에서 스킬 노드는 새 대화(앞 노드 대화를 모른다)로 이 줄들을 받는다 — 공통 규칙(있으면) · 단계 지시(이 SKILL.md) · 작업 폴더 · 작업 문서 · 런 입력 · 결과 파일. 그래서 스킬에는 이것만 쓴다:
  - **읽을 것** — 작업 문서의 어느 파일, 런 입력
  - **할 일과 남길 것** — 무엇을 만들어 어디에(작업 문서의 파일 이름 · 작업 폴더의 코드)
  - **판정** — 언제 「통과」, 언제 「실패」(고치면 되는 문제), 언제 「막힘」(사람이 정해야 함)
  - **하지 말 것** — 이 노드 밖의 일, 범위 밖 파일
- 결과 파일을 쓰는 법은 적지 않는다 — EDITH 가 런에서 따로 시킨다(`{"결과": "통과" | "건너뜀" | "실패" | "막힘", "한줄", "요약"}`). 조건이 안 맞아 할 일이 없는 단계면 「건너뜀」 으로 끝내라고만 적어 두면 런 화면에서 흐리게 묶인다.
- 일반 지시문으로 쓴다. 「SKILL.md 를 읽고 그대로 해」 로 불리므로 `context: fork` · `allowed-tools` · 동적 명령 삽입 같은 frontmatter 기능은 동작하지 않는다.
- 스크립트 · 보조 파일은 그 폴더 안에 둔다. 명령 노드는 자기 폴더 사본을 `$EDITH_ENGINE`, 작업 문서를 `$EDITH_WORK`, 런 입력을 `$EDITH_INPUT` 으로 받는다(작업 폴더에서 돈다). 무인 런(사람 없이 끝까지)이면 `$EDITH_UNATTENDED=1` · `$EDITH_RUN/run.json` 의 `"unattended": true` — 사람에게 묻는 카드 · 질문은 띄우지 말고 추천 · 가정으로 진행해 가정을 결과에 남긴다. EDITH 는 무인 런의 확인 필요 노드를 2번까지 다시 돌리고 그래도 안 되면 건너뛴다(까닭은 run.json 노드의 `reason` — 「무인 — 」 으로 시작).
- 명령 노드가 **끝 코드 77** 로 끝나면 그 노드가 든 체인 · 엔진의 남은 노드를 건너뛴다 — 이번 일에 없는 쪽을 통째로 넘길 때 그 체인 · 엔진 맨 앞에 둔다.
- 명령 노드가 `$EDITH_REWIND` 에 `{"to": "<노드 키>", "reason": "<이유>"}` 를 쓰고 끝 코드 0 으로 끝나면 그 노드부터 다시 돈다(뒤에 이어진 노드도 처음으로). 키는 돌리는 맨 바깥 엔진부터의 노드 id 를 `.` 로 이은 것(`n2.n3`) — 그 엔진으로 돌릴 때만 맞다. 되돌림 한도는 명령이 센다(`$EDITH_RUN/run.json` 의 `rewinds`). 보통 화살표로 고리를 만들지 않고 이것으로 되돌아간다. 스킬 노드는 결과 파일 옆에 같은 꼴의 `rewind.json` 을 결과 파일보다 먼저 쓰고 「통과」 로 끝낸다.
- **갈래** — 한 노드에서 화살표를 둘 이상 내면 그 뒤는 갈래마다 동시에 돈다(갈래마다 Claude pane 하나, 같은 작업 폴더 · 작업 문서). 다시 모으려면 갈래 끝들을 한 노드로 잇는다(그 노드는 다 끝나야 돈다). 갈래 이름은 갈라지는 자리의 노드 id 라, 이름을 정하려면 그 노드 id 를 짧게 짓는다(`be` · `fe`). 갈래끼리 같은 파일을 고치지 않게 나눈다.
- 스킬 노드의 Claude 모델 · 강도 · MCP 는 작업 문서의 `edith-claude.json`(갈래는 `edith-claude.<갈래>.json` 먼저) — `{"model", "effort", "mcpConfig": [절대 경로], "why"?}`. 앞 노드(명령 등)가 다음 스킬 노드 전에 쓴다. `why` 는 왜 그 설정인지 한 줄(화면 칩에 보이기만).
- 공방 「흐름 지도」 는 맨 위 엔진 폴더의 `map.json` 을 따른다(없으면 맨 위 노드마다 한 칸) — `{"summary", "phases": [{"name", "nodes"?: [맨 위 노드 id], "lanes"?: [{"name", "nodes"}]}], "hide"?: ["<노드가 든 폴더>/<노드 id>"](든 노드만 숨김 — 있으면 rest 는 무시, 나머지는 nodes 에 없어도 종류대로 보인다), "rest"?: "hidden"(hide 가 없을 때 nodes 에 없는 노드는 숨김), "fold"?: {"<엔진 폴더>": {"title", "role", "tag"?, "desc"?}}(그 폴더 안 노드를 한 줄로), "nodes": {"<노드가 든 폴더>/<노드 id>": {"role": claude|check|human|wait, "tag"?, "desc"?, "instr"?: [공방 폴더 기준 지시 파일]}}}`. 노드를 더하거나 옮기면 map.json 도 같이 고친다.
- 런 화면 단추는 맨 위 엔진 폴더의 `actions.json` — `[{"label", "command", "ask"?, "hint"?, "danger"?, "when"?}]`(ask 글은 `$EDITH_ACTION_TEXT`, hint 는 마우스를 올리면 보이는 한 줄 설명 — 단추마다 적는다, 지우는 단추는 `"danger": true`, 런이 끝난 뒤에만 쓰는 단추는 `"when": "done"`). `"on": "request"` 는 받은 요청을 열어 시작하거나 거절할 때 도는 명령(요청 쪽에 알리기 — `$EDITH_REQUEST_FILE` · `$EDITH_REQUEST_STATE` started|rejected · `$EDITH_REQUEST_RUN` · `$EDITH_REQUEST_REASON`, 요청으로 시작한 런은 작업 문서 `edith-request.json` 에 요청 전체 · meta). `"on": "picks"` 는 단추 대신 새 런 칸의 고르기 목록 — 그 명령이 표준 출력에 `[{"label", "note"?, "input"}]` JSON 을 내면 고른 `input` 이 입력칸에 들어간다(공방의 그 엔진 폴더에서 돈다, `$EDITH_ENGINE` · `$EDITH_WORKSHOP`). `"on": "results"` 를 붙이면 단추 대신 「결과」 화면에서 할 일 체크가 바뀔 때 돈다(`$EDITH_RESULT_TAG` · `_TITLE` · `_GROUP` · `_TEXT` · `_DONE`).
- 런 화면 「레포」 는 작업 문서의 `edith-repos.json` — `[{"path": "<레포 절대 경로>", "branch"?, "base"?, "also"?: ["origin/dev" 처럼 더 볼 기준], "start"?: "<워크트리를 딴 커밋>"}]`(런 작업 폴더 안 레포만, EDITH 는 읽기만 — `start` 를 주면 그 뒤 커밋이 없을 때 「커밋 없음」).
- 런 화면 「산출물」 은 작업 문서의 `edith-outputs.json` — `[{"label", "path"?: "<파일 절대 경로>", "url"?: "<http(s) 주소>", "node"?: "<만든 노드 키>", "note"?}]`(파일은 런 작업 폴더 · 실행 폴더 안의 글 파일만 보인다).
- 끝난 런 「요약」 은 작업 문서의 `edith-summary.json` — `{"title", "did": [한 일], "chips"?, "next"?: [{"label", "note"?, "action"?: "<런 단추 이름>", "done"?: true}], "check"?: [{"title", "note"?, "items"}], "outputs"?: [주요 산출물 이름]}`(런이 끝날 때 쓴다 — `did` 가 비면 요약 없음).
- 런이 브라우저를 띄우면 그동안 작업 문서에 `edith-live.json` — `{"port": <CDP 포트>}` 를 두고 닫을 때 지운다(런 화면 「브라우저 화면」).
- 런 분석에 엔진 기록을 같이 보이려면 작업 문서의 `edith-records.jsonl` 에 한 줄에 JSON 하나씩. Codex 사용량은 `{"kind": "usage", "node": "<노드 키>", "codex": {"in", "out", "cacheR"}, "weekly": <주간 한도 %>}` 줄로 남기면 분석이 더한다.
- 런이 끝난 뒤 사람이 할 일(배포 전 조치 · 확인할 것)은 작업 문서의 `edith-results.json` — `[{"tag": "<안건>", "title", "note"?, "items": [{"text", "done": false, "group"?}]}]`. EDITH 「결과」 화면이 모든 런의 것을 태그로 모아 체크하게 한다. 다시 쓸 때는 이미 체크된 할 일(같은 글)의 `done` 을 살린다.
- 모든 스킬에 같은 규칙(범위 · 금지 · 말투)이 필요하면 공통 규칙 스킬 하나로 빼고, 화면 「공통 규칙」 에서 고르라고 알려 준다.

## 4. 초안 쓰기 — `<폴더>/draft.json`

```json
{
  "name": "기획 파악",
  "nodes": [
    { "id": "n1", "title": "기획서 읽기", "skill": { "from": "engine", "id": "read-spec" } },
    { "id": "n2", "title": "미결 정리", "skill": { "from": "engine", "id": "open-questions" } },
    { "id": "n3", "title": "형식 확인", "command": "$EDITH_ENGINE/check.sh" },
    { "id": "n4", "title": "형식 고치기", "skill": { "from": "engine", "id": "fix-format" } },
    { "id": "n5", "title": "리뷰", "skill": { "from": "installed", "id": "claude:codex-review" } }
  ],
  "edges": [
    { "from": "n1", "to": "n2" },
    { "from": "n2", "to": "n3" },
    { "from": "n3", "to": "n4", "fail": true, "max": 2 },
    { "from": "n3", "to": "n5" }
  ]
}
```

엔진이면 노드가 체인 · 엔진을 가리킨다(`kind` 는 쓰지 않아도 된다 — 지금 종류를 따른다):

```json
{
  "name": "기능 개발",
  "nodes": [
    { "id": "n1", "title": "준비", "skill": { "from": "engine", "id": "prepare" } },
    { "id": "n2", "title": "기획 파악", "engine": "read" },
    { "id": "n3", "title": "구현 계획", "engine": "plan" }
  ],
  "edges": [{ "from": "n1", "to": "n2" }, { "from": "n2", "to": "n3" }]
}
```

- 노드 하나는 `skill` · `command` · `engine`(체인) 중 하나만. 노드 id 는 영문 소문자 · 숫자 · `-`.
- 그 폴더 스킬은 `{"from": "engine", "id": "<skills 폴더 이름>"}`. 설치 스킬 id 는 EDITH 스킬 화면의 id 와 같다 — 내 스킬 `claude:<이름>`, 공유 스킬 `shared:<이름>`, 플러그인 스킬 `claude:<플러그인>:<이름>`.
- `x` · `y` 는 빼도 된다(화면이 놓는다). 고치는 거면 그대로 둘 노드의 id 를 바꾸지 않는다(자리가 유지된다).
- 쓰기 전 점검: id 가 겹치지 않는다 · 화살표 양 끝이 있는 노드다 · 보통 화살표에 고리가 없다 · 실패 화살표 규칙(한 노드에 하나, 고치는 노드에는 다른 화살표 없음, 체인 · 엔진 노드에는 잇지 않음) · 초안이 쓰는 그 폴더 스킬 파일이 다 있다 · 체인이면 `engine` 노드가 없다 · `engine` 노드가 가리키는 폴더가 공방에 있다.
- `draft.json.tmp` 에 다 쓴 뒤 `mv` 로 옮긴다 — 화면이 반쯤 쓴 초안을 읽지 않게.

## 5. 끝나면

사용자에게 짧게 알린다: 노드 몇 개와 스킬 몇 개를 썼는지, EDITH 공방에서 「Claude 초안」 띠의 「미리 보기 → 적용」 을 누르라는 것, 화면에서 정할 것(작업 폴더 · 공통 규칙)이 있으면 그것.
